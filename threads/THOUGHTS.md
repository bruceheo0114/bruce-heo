# 스레드 생각 글 (사용자 결정 2026-10-11)

브런치 재가공(매일 12:30)과 별개로, 브루스가 **대화창에 보낸 생각·이슈 메모**를 스레드 글로 정리해 **승인받은 즉시** 올린다.
채널 안 역할: 스레드는 "지금 브루스가 하는 생각"이 보이는 유일한 채널이다. 반응 좋은 생각 글은 다음 브런치 글감 후보가 된다.

## 흐름
1. **메모 받기**: 거친 메모, 음성 받아쓰기, 기사 링크 + 한 줄 무엇이든.
2. **정리**: `THREADS.md` 의 목소리·3초 오프닝·"구조: 댓글 타래"를 그대로 따른다(본문 + replies 2~3개). 훅 유형은 요일 대신 메모에 맞는 걸 고른다.
   - 사실·의견은 **메모에 있는 것만**. 메모가 기사·이슈를 가리키면 원문을 한 번 확인하고, 숫자·주체·날짜는 확인된 것만 쓴다. 확인 못 하면 빼거나 브루스에게 묻는다.
   - 메모에 없는 경험담·사례를 지어내지 않는다. 내용이 모자라면 짧게 쓰거나 물어본다.
   - `reply_text`: 기사를 다뤘으면 출처 링크("원문 기사는 여기 👉 ..."), 아니면 관련 브런치 글이 있을 때만 그 링크, 둘 다 없으면 생략.
   - THREADS.md "지킬 것"(과장·반응 미끼·정치·사회 논란·남 비꼬기 금지)을 그대로 지킨다. 작성자 회사의 고객사와 그 직접 경쟁 제품군은 다루지 않는다(목록은 저장소에 적지 않는다 — 애매하면 브루스에게 묻는다).
3. **확인**: 대화창에 본문·타래 전문과 글자 수를 보여주고 승인을 받는다. 파일은 `threads/posts/thought-YYYY-MM-DD-N.json`, `"kind": "thought"`, `"status": "pending"` 으로 만들어 둔다. 수정 요청이 오면 고쳐서 다시 보여준다.
4. **게시(승인 즉시)**: "승인"·"올려" 등 명확한 승인을 받으면 status 를 `scheduled` 로 바꿔 main 에 푸시하고, Actions `threads-publish.yml` 을 `post_date: thought-YYYY-MM-DD-N` 으로 실행한다(GitHub MCP `actions_run_trigger`). 게시되면(파일 status `posted`) permalink 를 알려준다.
   - 예외: 승인 시각이 11:30~13:30 KST 면 12:30 정기 글과 겹치지 않게 `post_at: "14:00"` 을 함께 넣고 그렇게 알린다.
   - 하루 생각 글은 최대 2편.
5. 승인 없이는 절대 올리지 않는다. 승인 전 대화에서 "좋네" 같은 반응은 승인이 아니다 — 올릴지 한 번 더 묻는다.

## 파일 예
```json
{"date": "2026-10-11", "kind": "thought", "title": "메모 요지 한 줄", "hook_type": "논란형",
 "text": "본문", "replies": ["전환", "결과 + 질문"], "topic_tag": "마케팅",
 "reply_text": "원문 기사는 여기 👉 https://...", "status": "pending",
 "memo": "브루스가 보낸 메모 원문"}
```
