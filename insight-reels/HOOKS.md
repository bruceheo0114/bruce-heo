# 훅·구조 공통 규칙 (릴스 · 카드뉴스 · 스레드)

사용자 결정 2026-10-05: 모든 콘텐츠에 적용한다. 품질 규칙(원문 사실만, 광고주 익명, 과장 금지)이 이 규칙보다 앞선다.

## 1. 3초 오프닝
- **첫 1~2초(첫 줄·첫 장)에 스크롤을 멈춘다.** 정보·설명으로 시작하지 않는다. 장면·대사·의외의 숫자·반전 한 문장.
- **3초 안에 "끝까지 봐야 할 이유"를 만든다.** 답을 바로 주지 않고 질문을 남긴다(예: "실수가 아니었다", "진짜 이유는 따로 있었다").
- 릴스: 첫 장면 `punch` 가 첫 문장의 핵심 단어에 맞춰 0~1초 안에 터진다. 상단 title 은 훅을 반복하지 말고 질문으로 받는다.

## 2. 구조: 공감 → 문제 제기 → 전환 → 결과
1. **공감**: 보는 사람이 겪어 봤을 상황 하나.
2. **문제 제기**: 왜 대부분 여기서 틀리는지·막히는지.
3. **전환**: 원문 속 사례·판단이 뒤집는 지점.
4. **결과**: 그래서 무엇이 달라졌는지 + 한 줄 원칙.
- **중간 장치를 한 번 넣는다.** 다음이 궁금해지는 문장(예: "근데 진짜 이상한 건 그다음이었어", "여기서 갈린다"). 카드뉴스는 장 끝 문장을 다음 장으로 이어지게 쓴다.
- **끝은 저장·공유·팔로우로 자연스럽게.** 명령조("팔로우하세요!") 대신 이유를 붙인다(예: "다음 회의 전에 다시 볼 수 있게 저장해 둬요", "이런 브랜드 이야기 화·목마다 올려요"). 질문 하나 + 이 멘트 하나까지만.

## 3. 훅 7가지 패턴 — 돌려 쓴다
| 패턴 | 쓰는 법 | 예 |
|---|---|---|
| 숫자형 | 원문의 의외의 숫자 하나로 연다 | 조회수 200만인데 수세미 얘기는 한 줄도 없었다 |
| 반전형 | 상식과 반대인 결과 | 실수처럼 보였는데, 설계였다 |
| 실패 경험형 | 내가(또는 한 브랜드가) 틀렸던 순간 | 밈 하나 터뜨리고 브랜드는 아무도 기억 못 했다 |
| 비밀 공개형 | 현장에서만 아는 기준 하나 | 제안서 통과하는 팀은 RFP 를 거꾸로 읽는다 |
| 질문형 | 답하고 싶어지는 질문 | AI 한테 제품을 물어봐, 상황을 물어봐? |
| 비교형 | A vs B 로 판단을 세운다 | 팔로워 100만 vs 댓글 100개, 뭘 고를래? |
| 논란형 | 통념에 반대하는 소신(사람·브랜드 비방 아님) | 반복은 게으름이 아니다 |

- **저장·공유가 잘 나오는 쪽 우선**: 비밀 공개형·비교형·숫자형을 자주, 논란형은 주 1회 이하.
- 숫자·비밀·사례는 **원문에 있는 것만.** 없는 "비밀"을 만들지 않는다.

## 4. 원문 안내(광고처럼 보이지 않게)
- "더 읽을 거리"로 안내한다: "사례 전체랑 숫자는 브런치에 정리해 뒀어요", "원문에 체크리스트까지 있어요". "구독·좋아요 부탁" 같은 부탁형은 쓰지 않는다.

## 하지 않을 것
"댓글 남기면 DM" 같은 반응 미끼, "무조건·충격·역대급", 끝까지 답을 숨기는 낚시(3초에 연 질문은 반드시 본문에서 답한다).
